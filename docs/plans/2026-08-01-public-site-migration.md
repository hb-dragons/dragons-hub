# Public Site Migration Implementation Plan (hbdragons.de → dragons-all)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild hbdragons.de as a static Astro + React-islands app (`apps/site`) inside dragons-all, fed by a new Payload 3 CMS (`apps/cms`) and the existing `/public/*` API, with fully automated build+deploy to the existing Hetzner webspace, then cut over and tear down the legacy stack.

**Architecture:** Content lives in Payload 3 (thin Next app on Cloud Run, shared Cloud SQL, GCS media); the Astro site is pure-static (`output: 'static'`, no adapter) — content fetched from Payload REST at build time via Content Layer loaders, live sports data rendered client-side by React islands against `api.app.hbdragons.de/public/*`. GitHub Actions builds and SFTP-mirrors each release to `public_html/releases/<sha>` on Hetzner and flips an atomic `current` symlink through a token-authed `swap.php` (the webspace is SFTP-only — no ssh exec, no rsync). Rebuilds trigger on git push, Payload publish (`repository_dispatch: cms-publish`), sync completion (new `webhook` notification channel → `repository_dispatch: sync-completed`), manual dispatch, and a daily safety cron.

**Tech Stack:** Astro ^7.1.6 + @astrojs/react ^6.0.2 + React 19.2.6 + Tailwind ^4.3.0 (already validated on branch `prototype/astro-site`, commit 13f39d78); Payload 3.x (3.87.0 at time of writing, pin to 3.x — v4 is pre-alpha) + @payloadcms/db-postgres + richtext-lexical + storage-gcs on Next ≥16.2.2; Hono/Drizzle/BullMQ in apps/api as today; lftp + PHP on Hetzner for deploy.

## Global Constraints

- dragons-all is **pnpm@11 + Turborepo**, Node ≥ 22.12 — never bun here (the legacy tree stays bun and is not touched by this plan except at cutover).
- `packages/db`: **drizzle-kit generate + migrate only** — `push` is disabled repo-wide.
- Conventional commits; every task lands with tests; per-package coverage ratchets and repo guards (`check:design-tokens`, `check:ai-slop`, contract tests, knip) must stay green.
- Visual parity is a hard requirement: the new site keeps the current site's look **1:1**, achieved via `packages/ui/src/styles/site.css` theme *values* over the shared Dragon's Lair token *vocabulary* (`globals.css` = the vocabulary; never fork token names).
- Component reuse is **primitives-only**: @dragons/ui primitives (Button, Badge, Card, Skeleton, Tabs, …) in islands; composites and flair (Dither, Magnet, SpotlightCard, lightbox, GameCard, …) live in `apps/site`; promote to @dragons/ui only on a second consumer.
- **de-only, no i18n layer**: all UI strings in `apps/site/src/lib/strings.ts` (no sprinkled literals); URLs carry no locale prefix.
- URL parity 1:1 with the current site; trailing-slash canonical form (`build.format: 'directory'`, `trailingSlash: 'always'`); apex `hbdragons.de` is the canonical host.
- CMS surface is exactly the pruned set from the CMS decision: posts, pages, partners, projects, downloads, shop-items, timeline-items, people (ehrenamtliche) + vorstand + positions + trainers, teams, media, globals site-settings / team-background / background-video. **No** gym/schiedsrichter/probetraining/privacy-policy types; no CMS i18n.
- Hetzner webspace facts (verified live): SFTP-only (ProFTPD jail, home shown as `/`, docroot = `public_html` = `/usr/www/users/hbdrag`); **never create symlinks via SFTP** (leaves hidden dangling links); PHP runs as the account user — `symlink()` + `rename()` is the only atomic swap path; `.htaccess` `Options +FollowSymLinks` + mod_rewrite work.
- Legacy repair is out of scope: old site stays frozen (manual Cyberduck uploads if ever needed) until cutover.

```ts
// apps/cms/src/hooks/dispatch-rebuild.ts
import type { CollectionAfterChangeHook, CollectionAfterDeleteHook } from "payload";

async function dispatch(reason: string) {
  const token = process.env.GH_DISPATCH_TOKEN;
  if (!token) return;
  try {
    await fetch("https://api.github.com/repos/hb-dragons/dragons-hub/dispatches", {
      method: "POST",
      headers: { Authorization: `Bearer ${token}`, Accept: "application/vnd.github+json" },
      body: JSON.stringify({ event_type: "cms-publish", client_payload: { reason } }),
    });
  } catch (err) { console.error("rebuild dispatch failed", err); }
}

export const dispatchOnPublish: CollectionAfterChangeHook = async ({ doc, previousDoc, req, collection }) => {
  if (req.context?.skipRebuild) return doc;
  const was = previousDoc?._status, is = doc?._status;
  const publishedChanged = is === "published" || (was === "published" && is !== "published");
  const draftless = is === undefined; // collections without drafts: every change is live
  if (publishedChanged || draftless) await dispatch(`${collection.slug} change`);
  return doc;
};

export const dispatchOnDelete: CollectionAfterDeleteHook = async ({ req, collection }) => {
  if (!req.context?.skipRebuild) await dispatch(`${collection.slug} delete`);
};
```

Attach via `hooks: { afterChange: [dispatchOnPublish], afterDelete: [dispatchOnDelete] }` on every content collection and `afterChange` on globals. No debounce here — the deploy workflow's `concurrency` group coalesces bursts.

```ts
import type { Loader } from "astro/loaders";

export function payloadLoader(collection: string, opts: { depth?: number; sort?: string } = {}): Loader {
  return {
    name: `payload:${collection}`,
    async load({ store, parseData }) {
      const base = process.env.CMS_URL!;
      const headers = { Authorization: `users API-Key ${process.env.CMS_API_TOKEN}` };
      store.clear();
      for (let page = 1; ; page++) {
        const url = `${base}/api/${collection}?limit=100&page=${page}&depth=${opts.depth ?? 1}` +
          (opts.sort ? `&sort=${opts.sort}` : "");
        const res = await fetch(url, { headers });
        if (!res.ok) throw new Error(`payload ${collection}: HTTP ${res.status}`);
        const json = await res.json();
        for (const doc of json.docs)
          store.set({ id: String(doc.id), data: await parseData({ id: String(doc.id), data: doc }) });
        if (!json.hasNextPage) break;
      }
    },
  };
}

export async function getSiteSettings() { /* GET /api/globals/site-settings, same headers */ }

            set sftp:connect-program 'ssh -a -x -i ~/deploy_key -o StrictHostKeyChecking=accept-new';
            open sftp://${{ vars.HETZNER_USER }}@${{ vars.HETZNER_HOST }};
            mirror -R --parallel=4 apps/site/dist public_html/releases/${GITHUB_SHA};
            put -O public_html apps/site/deploy/swap.php;
            bye"
      - name: Swap
        if: inputs.sha == ''
        run: |
          curl -fsS -X POST "https://hbdragons.de/swap.php" \
            -H "X-Deploy-Token: ${{ secrets.HETZNER_DEPLOY_TOKEN }}" \
            --data "sha=${GITHUB_SHA}"
      - name: Smoke test
        run: |
          curl -fsS https://hbdragons.de/ | grep -qi dragons
          test "$(curl -s -o /dev/null -w '%{http_code}' https://hbdragons.de/definitely-not-a-page/)" = 404
```
